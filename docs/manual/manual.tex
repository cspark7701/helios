\chapter{System Overview and Architecture}

\section{Introduction}
\textbf{HELIOS} (\textbf{HE}avy ion \textbf{L}inac \textbf{I}ntelligent \textbf{O}rchestration) is a distributed multi-agent artificial intelligence framework engineered for commissioning, operating, and optimizing heavy-ion linear accelerators (LEBT, RFQ, MEBT, SCL, and HEBT).

Aligned directly with the \textbf{Plan-First} paradigm established by the Lawrence Berkeley National Laboratory (LBNL) Osprey architecture, HELIOS enforces strict separation of concerns between optimization heuristics, digital twin simulation validations, deterministic safety gatekeepers, and hardware control layers.

\begin{figure}[h!]
\centering
\includegraphics[width=\textwidth]{architecture.png}
\caption{HELIOS System Architecture: Layered Plan-First multi-agent framework inspired by LBNL Osprey, showing progressive flow from operator interfaces down to physical accelerator hardware through deterministic safety gatekeepers and EPICS connectors.}
\label{fig:architecture}
\end{figure}

\section{Core Architectural Principles}
\begin{enumerate}
    \item \textbf{Pre-Flight Simulation Verification}: No setpoint is ever delivered to live hardware without prior validation through high-fidelity codes (ANL TRACK via Wine, LBNL IMPACT-Z via \texttt{lume-impact}) or sub-millisecond neural surrogates.
    \item \textbf{Deterministic Safety-First Actuation}: Optimization algorithms do not talk directly to EPICS. All actuations pass through rate-of-change limiters, slew rate clamps, discrete DAC current steps, and the \texttt{SafetyAgent} rollback stack.
    \item \textbf{Plan-First Execution Lifecycle}: High-level natural language goals are first compiled into structured, reproducible execution plans:
    \begin{equation*}
    \begin{aligned}
    \text{DRAFT} &\longrightarrow \text{SIMULATION\_VERIFIED} \longrightarrow \text{SAFETY\_APPROVED} \\
    &\longrightarrow \text{EXECUTING} \longrightarrow \text{COMPLETED}
    \end{aligned}
    \end{equation*}
    \item \textbf{Dynamic Capability Classification (Osprey Pattern)}: Instead of injecting hundreds of tools into the LLM context, HELIOS dynamically filters capabilities based on the operator's intent and domain keywords, keeping prompt sizes compact and execution deterministic.
    \item \textbf{Graduated Autonomy}: Enforces clear human-in-the-loop sign-offs graduated from Advisory (Level 0) to Fully Autonomous (Level 4).
\end{enumerate}

\section{Agent Taxonomy and Roles}
The framework partitions operational responsibilities among specialized autonomous agents:
\begin{enumerate}
    \item \textbf{Master Orchestrator Agent (\texttt{HELIOS-Orchestrator})}: Decomposes high-level physicist directives into formal execution plans, manages multi-agent coordination, and interfaces with human operators.
    \item \textbf{Physics and Simulation Agent (\texttt{HELIOS-Physics})}: Manages the digital twin model, executes ANL TRACK and LBNL IMPACT-Z simulations, and evaluates deep neural surrogate models.
    \item \textbf{Diagnostics and Telemetry Agent (\texttt{HELIOS-Diagnostics})}: Ingests real-time signals from Beam Position Monitors (BPMs), Beam Loss Monitors (BLMs), and wire scanners; evaluates beam transmission and detects operational anomalies.
    \item \textbf{Tuning and Optimization Agent (\texttt{HELIOS-Tuner})}: Executes algorithmic optimization including response-matrix SVD orbit correction, multi-objective Bayesian Optimization, and Reinforcement Learning continuous control.
    \item \textbf{Safety and Verification Agent (\texttt{HELIOS-Safety})}: Serves as a deterministic gatekeeper enforcing hard software limits, slew-rate constraints, cryo-quench margins, and instant rollback stacks.
    \item \textbf{Control and Hardware Interface Agent (\texttt{HELIOS-Control})}: Interfaces with the live control system via EPICS Channel Access (CA) and pvAccess (PVA) with atomic readback verification.
\end{enumerate}

\chapter{Installation and Environment Setup}

\section{Prerequisites and Python Support}
HELIOS is tested and verified across Python 3.10 through 3.14 (recommended: Python 3.11 in Conda/Miniforge).

\begin{lstlisting}[language=bash]
# Clone repository
git clone https://github.com/cspark/helios.git
cd helios

# Create and activate conda environment
conda create -n helios python=3.11 -y
conda activate helios

# Install in editable mode with all dependencies (dev, rl, ml, epics, dashboard, ontology)
pip install -e ".[all]"

# Or select specific optional extras:
pip install -e ".[dev,ml,dashboard,ontology]"
\end{lstlisting}

\section{Automated Environment Loader (\texttt{setup.sh})}
HELIOS provides an automated shell script \texttt{setup.sh} that automatically detects Conda/Miniforge or local virtual environments (\texttt{.venv}), exports project roots, and configures external accelerator simulation tool paths:
\begin{lstlisting}[language=bash]
# Source the environment configuration
source setup.sh
\end{lstlisting}
This exports \texttt{PROJECT\_ROOT}, \texttt{HELIOS\_ROOT}, \texttt{TRACK\_ROOT}, and \texttt{TRACK\_EXE\_PATH}, ensuring seamless execution of physics solvers across all subsystems.

\section{Containerized Deployment (Docker \& Docker Compose)}
HELIOS provides a production-ready, multi-stage \texttt{Dockerfile} and \texttt{docker-compose.yml} for isolated containerized execution in control rooms and cluster environments without manual local dependency installation.

\subsection{Building and Running with Docker}
The container packages Python 3.11, Wine 64-bit (for ANL TRACK ray-tracing simulation), build toolchains, and EPICS networking:
\begin{lstlisting}[language=bash]
# Build the production Docker image
docker build -t helios-orchestrator:latest .

# Run the container launching the Web Dashboard
docker run -d --name helios-app -p 8000:8000 helios-orchestrator:latest
\end{lstlisting}
The web operator dashboard is then accessible at \url{http://localhost:8000}.

\subsection{Distributed Deployment with Docker Compose}
HELIOS employs an asynchronous Redis message broker (\texttt{helios-redis}) on port 6379 to coordinate multi-agent operations:
\begin{lstlisting}[language=bash]
# Launch full orchestrator and Redis stack in background
docker compose up -d

# Inspect live orchestrator logs
docker compose logs -f helios-orchestrator

# Shutdown services
docker compose down
\end{lstlisting}

\subsection{EPICS Host Networking and Volume Mounting}
When connecting to live facility hardware (e.g. RAON, FRIB) or local simulation decks, attach host networking for Channel Access broadcast discovery and mount model directories:
\begin{lstlisting}[language=bash]
# Run with host networking and local deck mounts
docker run -it --rm --net=host \
  -v $(pwd)/examples:/app/examples \
  -v $(pwd)/docs/exec-plans:/app/docs/exec-plans \
  -e EPICS_CA_ADDR_LIST="10.0.0.255" \
  -e EPICS_CA_AUTO_ADDR_LIST="NO" \
  helios-orchestrator:latest \
  helios tune-orbit --section MEBT --autonomy 2
\end{lstlisting}

\subsection{Executing Commands within Running Containers}
Commissioning routines and interactive shells can be invoked inside an active container:
\begin{lstlisting}[language=bash]
# Execute CLI commissioning commands
docker exec -it helios-app helios tune-orbit --section MEBT
docker exec -it helios-app helios chat
docker exec -it helios-app helios report --facility "RAON SCL1"

# Access interactive container shell
docker exec -it helios-app bash
\end{lstlisting}

pyinstaller --name=helios --onefile --clean helios/cli/main.py

\chapter{Accelerator Physics and Heavy Ion Dynamics}

\section{Multi-Species and Multi-Charge-State (MCS) Dynamics}
Heavy-ion linacs frequently accelerate multi-charge state beams simultaneously (e.g., $^{238}\text{U}^{33+}$ and $^{238}\text{U}^{34+}$). The magnetic rigidity $B\rho$ is given by:
\begin{equation}
    B\rho = \frac{p}{q} = \frac{\gamma m_0 \beta c}{q}
\end{equation}
The module \texttt{helios.physics.species} models isotopic distributions and composite beam centroids across charge fractions:
\begin{equation}
    \bar{x}(z) = \sum_{q} f_q \, x_q(z)
\end{equation}

\section{Steerer Current Actuation and Quantization}
Dipole correctors apply a magnetic kick deflection angle $\theta$:
\begin{equation}
    \theta = \frac{B_y L_{\text{eff}}}{B\rho}
\end{equation}
The power supply current $I$ is calibrated linearly via $I = k_{\text{conv}} \cdot \theta$ ($k_{\text{conv}} \approx 0.168\text{ A/mrad}$). Digital-to-analog converter (DAC) discretization is modeled by:
\begin{equation}
    I_{\text{quantized}} = \text{round}\left(\frac{I}{\Delta I}\right) \cdot \Delta I, \quad \Delta I = 0.05\text{ A}
\end{equation}
ensuring realistic simulation of power supply controller limits.

\section{Orbit Response Matrix (ORM) Inversion}
For $M$ BPMs and $N$ steerers, the trajectory response is $\Delta \vec{x} = \mathbf{R} \Delta \vec{\theta}$. Correction setpoints are computed via Singular Value Decomposition:
\begin{equation}
    \mathbf{R} = \mathbf{U} \mathbf{\Sigma} \mathbf{V}^T \implies \Delta \vec{\theta} = -\mathbf{V} \mathbf{\Sigma}^+ \mathbf{U}^T \vec{x}_0
\end{equation}

\section{RFQ 3D Vane Modulation and Cell Dynamics}
The module \texttt{helios.physics.rfq} simulates cell-by-cell vane modulation ($m(z), a(z), l(z)=\beta\lambda/2$) across Radial Matching, Shaper, Gentle Buncher, and Accelerator sections with 3D field expansion:
\begin{equation}
    U(r, \psi, z) = \frac{V_0}{2} \left[ \left(\frac{r}{r_0}\right)^2 \cos(2\psi) + A_{10} I_0(k r) \cos(k z) \right]
\end{equation}

\section{Solid and Liquid Metal Stripper Targets}
\begin{itemize}
    \item \textbf{Solid Carbon Foils (\texttt{helios.physics.stripper})}: Energy loss $\Delta E$, multiple Coulomb scattering angular spread $\theta_{\text{rms}}$, and radiation damage lifetime.
    \item \textbf{Liquid Lithium Strippers (\texttt{helios.physics.liquid\_stripper})}: Film hydrodynamics (Weber number $We$), multi-kW beam heating dissipation, and Langmuir evaporation rates.
\end{itemize}

\section{Magnetic Bunch Compressor Chicane}
The \texttt{helios.tuning.bunch\_compressor} module models 4-dipole C-type chicanes with momentum spread $\delta = \frac{1}{\beta^2} \frac{\Delta E}{E_{\text{tot}}}$:
\begin{equation}
    R_{56} \approx -2 \theta_b^2 \left( L_d + \frac{2}{3} L_b \right), \quad z_f = z_i + R_{56} \delta + T_{566} \delta^2
\end{equation}
computing optimal RF chirp $h = d\delta/dz$ for bunch compression factor $C > 1.0$.

\section{Linac Ultra-High Vacuum and Gas Stripping Losses}
The \texttt{helios.physics.vacuum} module evaluates molecular conductance, cryo-pumping speeds at 2 K, and heavy-ion electron loss cross-sections $\sigma_{\text{strip}}$:
\begin{equation}
    I(z) = I_0 \exp\left( -\int n_{\text{gas}}(z) \sigma_{\text{strip}} \, dz \right)
\end{equation}
mitigating ion-induced desorption runaway.

\section{Space-Charge Equipartitioning and Hofmann Stability}
The \texttt{helios.physics.equipartition} module calculates kinetic temperature anisotropy:
\begin{equation}
    \frac{T_\perp}{T_\parallel} = \frac{\varepsilon_{\perp n} \sigma_\perp}{\varepsilon_{\parallel n} \sigma_\parallel}
\end{equation}
and automatically rematches phase advances away from parametric resonance stopbands ($2\sigma_t - \sigma_l = 0$).

\section{High-Power Beam Dumps and Thermo-Mechanical Shock}
The \texttt{helios.physics.beam\_dump} module calculates heavy-ion Bragg peak energy deposition up to 400 kW, Grüneisen hydrodynamic shock pressure $P_{\text{shock}} = \Gamma \rho_0 e_{\text{dep}}$, von Mises thermal stresses, and Tong critical heat flux cooling margins.

\chapter{Superconducting RF Dynamics and Conditioning}

\section{Lorentz Force Detuning and Microphonics Feedforward}
Dynamic Lorentz Force Detuning under accelerating gradient:
\begin{equation}
    \Delta f_{\text{LFD}} = -K_L E_{\text{acc}}^2
\end{equation}
is compensated via normalized Filtered-X Least Mean Squares (FxLMS) piezo feedforward cancellation (\texttt{helios.rf.microphonics}), yielding $>10\text{ dB}$ jitter reduction.

\section{Cryoplant Heat Load Balancing}
The \texttt{helios.rf.cryoplant} module evaluates BCS surface resistance $R_{\text{BCS}} \propto \frac{f^2}{T} \exp(-\Delta/k_B T)$ and dynamic dissipation $P_{\text{loss}} \propto V_{\text{acc}}^2 / R_s$, optimizing cavity field distributions within 2.0 K cryogenic capacity.

\section{RF Multipactoring and Dark Current Field Emission}
The module \texttt{helios.rf.multipactor} models electron multipactoring resonances in coaxial couplers and cavities, alongside Fowler-Nordheim dark current field emission with bremsstrahlung radiation accumulation.

\section{Progressive RF Conditioning Sequencer}
The \texttt{AutonomousRFConditioner} automates forward power ramping with vacuum back-off interlocks ($P_{\text{vac}} < 10^{-7}\text{ mbar}$) and $+25\%$ power jump breakthroughs across multipacting zones.

\chapter{Deterministic Safety, Fast MPS and Rollback}

\section{Sub-Microsecond Fast MPS and Differential Beam Abort}
The \texttt{helios.safety.fast\_mps} module monitors ACCT differential beam loss ($\Delta I > \Delta I_{\text{threshold}}$) and fast diamond BLMs, initiating LEBT chopper deflection and RFQ shutdown in $<2.8\ \mu\text{s}$.

\section{Rollback Stack Architecture}
Prior to any hardware setpoint write, the \texttt{SafetyAgent} pushes current valid states to a rollback stack. Sensor threshold trips immediately trigger atomic parameter rollbacks.

\section{Radiological Activation and RPO Clearance}
The module \texttt{helios.safety.activation} models multi-isotope Bateman decay equations across induced radioisotopes ($^{56}\text{Mn}$, $^{58}\text{Co}$, $^{54}\text{Mn}$, $^{60}\text{Co}$), enforcing mandatory tunnel cooldown wait times and RPO cryptographic clearance tokens.

\section{Understanding Test Coverage in Accelerator Software}
Test coverage quantitatively measures the proportion of code executed by the automated test suite:
\begin{itemize}
    \item \textbf{Statement Coverage}: Ensures that every line of executable code has run, eliminating unresolved symbol references, missing imports, and runtime type/attribute crashes.
    \item \textbf{Branch Coverage}: Ensures both normal beam operation paths and machine protection interlock trip/fallback conditions are verified.
    \item \textbf{Guarantees}: Eliminates unexercised dead code, detects regressions instantly on refactoring, and ensures emergency rollback paths are functional.
\end{itemize}
Detailed technical patterns and coverage inspection procedures are documented in \url{docs/test_coverage_guide.md}.
